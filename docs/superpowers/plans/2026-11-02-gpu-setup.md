# GPU setup implementation plan

Execute inline using executing-plans, TDD, verification-before-completion and one fresh review.

Goal: a simple, safe stronger-model setup with read-only account verification and frozen GPU training packages, without launching cloud compute.
Spec: ../specs/2026-11-02-gpu-setup-design.md

Global constraints: no paid calls, remote apps or business-data transfer; preserve existing local training; credentials never in responses/logs/exports/browser storage; fixed model revision and package source; no training success labels before real GPU verification.

Review focus: a connection cannot launch compute; stale or foreign jobs cannot be packaged; secrets and held-out targets cannot leak; bad/slow connection responses cannot erase a replacement form; a planning allowance must never imply a hard provider cap.

### 1. Scoped packages and protected credentials
Files: own/gpu_setup.py, own/credential_vault.py, tests/test_gpu_setup.py.
- [ ] Write and observe failing tests for DPAPI/credential redaction, scope, stale confirmation, permission, frozen package contents and payload minimization.
- [ ] Implement local preparation records and fixed profiles/quotes; verify tests and commit.

### 2. SDK setup and portable GPU training
Files: own/gpu_install.py, gpu/train_on_gpu.py, gpu/training_core.py, gpu/run_model.py, tests/test_gpu_package.py.
- [ ] Add failing tests for independent launch approvals, known base/config, safe artifact output and separated check targets.

- [ ] Verify tests, SDK commands and a local CPU smoke of the shared training core using the installed tiny base. Commit.

### 3. Guided setup API and UI
Files: own/api.py, web/gpu.js, web/app.js, web/training.js, web/styles.css, tests/test_gpu_api.py, tests/browser/gpu-setup.cjs.

### 4. Review and handoff
Files: README.md, NEXT_STEPS.md, VERIFICATION.md, DESIGN.md, UX-CONTRACT.md.
